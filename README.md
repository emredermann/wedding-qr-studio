# Wedding QR Studio

Guests scan a QR code and upload photos, videos and voice messages from their phones. Media goes **straight from the browser to Cloudflare R2** through presigned PUT URLs, so the Next.js server never handles media bytes.

## Stack

- Next.js 16 (App Router, `src/proxy.ts` for session refresh), strict TypeScript, Tailwind v4, Lucide
- Supabase (`@supabase/ssr`, Postgres, `pgvector`, RLS)
- Cloudflare R2 (`@aws-sdk/client-s3`, `@aws-sdk/s3-request-presigner`)
- `@vladmandic/face-api` (client-side 128-d embeddings), `archiver` (streaming ZIP), `qrcode.react`

## Setup

1. `npm install`
2. `cp .env.example .env.local` and fill in the values.
3. Apply `supabase/migrations/0001_init_schema.sql`, either in the Supabase SQL editor or with `supabase db push`.
4. Set R2 bucket CORS from `infra/r2-cors.json`. Put your real origins in `AllowedOrigins`.
5. Enable public access on the bucket (custom domain or r2.dev) and set `R2_PUBLIC_URL`.
6. `npm run dev`

## Upload flow

```
Browser ──POST /api/upload/presign {albumId,fileName,fileType,fileSize}──▶ Next.js (validate album + MIME + size)
        ◀──── { uploadUrl, headers, fileKey, publicUrl } (600 s) ──────────┘
Browser ──PUT bytes (exact Content-Type / Content-Length)────────────────▶ Cloudflare R2
Browser ──POST /api/upload/complete {albumId,fileKey,...}────────────────▶ Next.js ──HEAD──▶ R2
                                                                                  └─INSERT media──▶ Postgres
```

- Object keys are generated by the server: `albums/${albumId}/${uuid}.${ext}`.
- Each URL signs `Content-Type` and `Content-Length`, so the stored object is exactly what was validated.
- `complete` takes size and type from R2 itself, not from the client. Rejected objects are deleted. The call is idempotent on `file_key`.
